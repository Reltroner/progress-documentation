## 1. The learning model: Worldbuilding as a reasoning laboratory

A fictional-world decision provides a controlled, accessible use case. The goal is to develop **portable reasoning procedures**—not to pretend the fictional world's facts transfer to reality. A student practices the procedure with their own world, articulates the abstract model, then uses a **safe unfamiliar everyday scenario** to ask whether the model remains useful.

**Learning chain:** `recognize a relevant decision → define a bounded problem → state assumptions → model actors/constraints/dependencies → compare alternatives → trace potential effects → ask what evidence is missing → propose a reversible test → revise the model`.

## 2. Four layers of evidence

| Layer | What is actually shown | What remains unproven |
| --- | --- | --- |
| **W — World usage** | An original fictional problem is coherently reasoned through | Real-world validity or transfer |
| **M — Mental-model explanation** | The learner can name a pattern without fictional nouns and describe how it operates | Application without prompts |
| **N — Near transfer** | The learner adapts it to a new fictional situation, genre, or scale | Independent non-fiction transfer |
| **X — Cross-domain case** | The learner selects and rechecks a model on an unfamiliar low-risk everyday problem | Long-term effectiveness or professional competence |

**Rubric safety:** independent cross-domain assessment must use actual observable novel-case evidence. Attention, quiz recall, attractive fiction and an analogy statement alone cannot serve as a proxy. One trial never proves general effectiveness.

## 3. Transfer method and explicit failure conditions

1. **Name the real decision** including goals, actors and constraints; the learner can choose a hypothetical, low-risk case.
2. **Abstract the model**, stripping out fictional rules, names and assumed outcomes.
3. **Check correspondence:** `maps` vs `does not map`. A valid response may reject the analogy entirely.
4. **Identify evidence:** what must be observed, asked, read or validated in the new field? Do not fabricate facts.
5. **Compare two options**, possible benefits, costs, counterfactuals and stakeholder effects.
6. **Test safely or defer:** choose a reversible action with an observable signal, or state why acting is inappropriate.
7. **Update the model:** document what surprised the learner and which hypothesis changed.

**Never use a fictional institutional model to justify an unverified real law, diagnosis, medical or financial decision, engineering safety intervention, personnel action or general claim about a community.** Real contexts need real constraints, domain knowledge and potentially qualified assistance. An individual may learn a useful mental model without becoming professionally competent in that domain.

## 4. Transfer scaffolding by course stage

| Stages | Required learning focus | Transfer depth |
| --- | --- | --- |
| Modules 01–02 | Meaningful usage and understandable vocabulary | Observe / identify a possible analogy (optional) |
| Modules 03–04 | Assumptions, constraints, perspective | Guided comparison; explicitly name a mismatch |
| Modules 05–07 | Dependencies, causality, alternatives, communication | Compare possible outcomes, justify uncertainty and a bounded test |
| Module 08 and capstone | Independent model selection and revision | One previously unseen low-risk non-fiction case, assessed separately |

The full mapping below is for **lesson authors**, not 89 mandatory extra exercises. Keep introductory lessons beginner-friendly; external probes may live in a small optional reflection area. The creator's own fictional world remains the central project.

## 5. Worked transfer case: two contexts, one tentative reasoning form

**Fictional use:** in Lumenhaven, an archive's permission check is a prerequisite for a teacher to use a memory recording. If the check changes, teaching plans can change.

**Abstract mental model:** `task B depends on verified condition A`. This is a useful *candidate* dependency model, not evidence about any real-world school.

**Unfamiliar low-risk everyday scenario:** a hobby group prepares a presentation; a speaker waits for a teammate's draft. A learner should **verify** the deadline, what must be supplied, and alternative ways to proceed, rather than inventing cooperation or assuming any particular outcome.

| Transfer audit | Example response |
| --- | --- |
| **Maps** | A necessary input precedes a downstream task; delays can propagate |
| **Does not map** | Fictional memory mechanics, authorities and consent rules have no automatic real-world counterpart |
| **Unknown** | Real handoff deadline, availability of the draft, participant constraints, fallback materials |
| **Two options** | Confirm handoff and wait with a fallback ready; or adapt the presentation to independent material |
| **Bounded test** | Request a deadline clarification and prepare a non-destructive draft |
| **Feedback** | Did the dependency really exist as assumed? Was an alternative feasible? What changes next? |

The student's explanation may support a **bounded** conclusion about their reasoning, not a claim that every team or planning situation follows the same dynamics.
