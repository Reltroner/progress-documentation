# 05 — Ratified Two-Phase Strategic Transition Contract

> Status: **RATIFIED_STRATEGY** (2026-10-12).  
> Current snapshot: **PHASE_1_NOT_YET_ACCEPTED**; Phase 2 is **NOT ACTIVE**.  
> Engineering work remains independently gated by LMS contract/owner authorization.

## Two distinct operating modes

~~~text
PHASE 1: BUILD → VERIFY → STABILIZE → FREEZE
          | LMS final accepted production DoD
          | reltroner.com front-end landing improvement
          | operational handoff/maintenance plan
          ↓
       OWNER PHASE 1 EXIT RECEIPT
          ↓
       FOUNDER READINESS CHECK
          ↓
       EXPLICIT PHASE 2 ACTIVATION
          ↓
PHASE 2: LISTEN → CONTRIBUTE → CONNECT → LEARN → REFINE
         default engineering = maintenance-first / evidence-driven
~~~

The phases alter the **optimization target**, not the studio's identity or permission boundaries.

## Phase 1 deliverables
**LMS:** 100% of the *already approved/frozen final scope*, with all mandatory business, authorization, integration, runtime/security, infrastructure, monitoring and recovery gates accepted as required by the LMS's own contracts. A Phase 3 source acceptance/CI merge is not a production-ready certificate. Do not invent final DoD from this archive.

**reltroner.com:** front-end-only landing page improved to professional minimum UX; Skill-Wanderer is an inspiration for information architecture, not a copied design, implied service offering or requirement to become a software outsourcing company. Requirements: intelligible value, two entry routes (creators/readers), relevant proof, accessible responsive UI, legible navigation, honest CTAs, functional routes, acceptable performance, and no unready paid features portrayed as live.

**Operations:** release evidence, known-good versions, incident/backup/restore path, monitoring ownership, bounded backlog and accepted limitations.

## Exit acceptance conditions
- All mandatory approved LMS DoD acceptance evidence is linked with exact scope, timestamp and owner.
- reltroner.com UX/functional test is accepted.
- Security/operational handoff is accepted.
- Owner issues an explicit Phase 1 closure, not merely a feeling of finishing.

**100% does not mean infinite perfection or delivery of all future feature ideas.** New AI agents, wiki automation, dashboard redesign, analytics or cross-channel features become change proposals and can be deferred. Conversely, mandatory agreed requirements cannot be hidden as deferrals without deliberate contract amendment.

## Phase 2 entry readiness
Mandatory: Phase 1 closure plus minimum sustainable founder readiness:
- true value explanation in ~15-second, ~1-minute and ~5-minute levels;
- some original inspectable, spoiler-safe creative framework examples;
- familiarity with chosen community rules and cultural context;
- manageable time/energy budget for responses/learning;
- explicit founder approval to switch dominant focus.

**Not mandatory:** thousands of followers; public Season 1; first sale; full communications mastery; a new Discord server.

## Phase 2 lifecycle
**2A Observe:** listen, map concerns and terminology; samples are not market-wide statistics.
**2B Participate:** useful feedback and discussion before linking owned assets.
**2C Relate:** repeated voluntary contact; identify genuine learning needs.
**2D Evaluate:** comprehension, transferability, actual cost, engagement quality, next experiments.

Initially prioritize a few channels, rather than five simultaneous operations. Candidate roles: Reddit r/worldbuilding (peer critique), LinkedIn (professional credibility), Discord (recurring conversation), Instagram (visual concepts), Threads (short exploratory prompts).

## Phase 2 engineering re-entry matrix

| Trigger | Action |
|---|---|
| incident, exposed data, security vulnerability | appropriate priority controlled correction |
| broken accepted user journey / accessibility blocker | bounded remediation |
| evidence of repeated important learner/business need | discovery → scope → cost/benefit → ADR/change control → acceptance |
| purely interesting tool/AI tech or vanity UI overhaul | backlog, **not** authorized work |
| new unrelated project | outside default Phase 2 scope |

Engineering is not forbidden; avoid reactivating costly project-building without meaningful delivery need. Preserve patching, incident response, backups and monitoring.

## Phase sequencing versus history
Historical discussion explored distribution-before-Season-1, freelancing, software startups and monetization, but the **later owner-ratified plan** prioritizes **LMS + landing closure before active community-brand campaigns**. Existing low-pressure public portfolio artifacts need not be removed, and a new founder decision may later revise strategy explicitly.
